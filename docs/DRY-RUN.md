# Steam discovery and install preview (m026)

This is a read-only core with injected evidence, not a Windows installer or a live
Steam scanner. No game, registry, process enumeration, UAC, subprocess or file
write is performed by these modules. The demonstration uses invented in-memory
files only; even its executable payload is a short ASCII sentence, not a PE file.

Run from the repository root with the existing Python:

```text
python -B tools/check.py
python -B tools/dry_run_demo.py
```

Do not provide `--game-exe` or `LD2_TEST_EXE` for the synthetic-only run. The
licensed-input integration test reports SKIPPED. Windows native encoding checks
run only when the standard Windows APIs are available; they are not game tests.

## Evidence ports

`discover_from_registry_values(provider, app_id, fs)` accepts a callable returning
explicit Steam roots. There is no registry adapter. Missing AppID does not call
the provider or filesystem. A denied provider reports `registry_access_denied`
without another lookup. Only named library and app manifest files are requested;
there is no disk scan or save access. Missing or malformed library enumeration
marks the result incomplete. A missing app manifest in an enumerated library is
a not-installed observation; any other manifest uncertainty blocks readiness.

Modern and legacy `libraryfolders.vdf` are accepted. Every candidate retains its
library and manifest provenance. More than one candidate requires an explicit
selection; a selection must refer to a discovered candidate. `manual_candidate`
validates a separately supplied directory with the same guards and explicit
AppID. A future UI may wrap that result in `Discovery(..., complete=True)` only
for the explicitly selected manual scope, never to erase a failed Steam scan.

`ReadOnlyFS` exposes just `metadata` and bounded `read_bytes`. Metadata must report
canonical path, file identity, reparse and ancestor checks, size, change token
and EXE file version. Existing paths without identity, ambiguous paths and
unverified ancestors are rejected. Reads compare metadata before and after.
Windows drive-absolute Unicode/space paths are supported; relative, UNC/device,
traversal, alternate-stream, reserved-device and trailing-dot/space paths are
rejected conservatively. VDF reads have a 2 MiB cap; EXE/backup reads a 32 MiB cap;
root/library counts and expanded path length are bounded.

`ProcessEvidence` must affirm a complete check with no unresolved game processes.
Any reported game instance, including another copy, blocks readiness. An empty
list without complete evidence is not proof that the game exited.

These ports are a trust boundary: the core cannot prove injected metadata is
truthful. `complete=True` is not OS attestation. The synthetic adapter supplies
invented identities. A production Windows adapter still needs handle-based
identity/reparse checks, correct missing-ancestor semantics and complete process
access handling. Lexical case-folding is not a substitute for Windows file IDs.
Pre/post metadata comparisons do not solve adversarial races, hard links, aliases
or changes after preview. Revalidate under transaction locks before any future
write. No production OS adapter or transaction implementation is delivered here.

## Plan results

`plan_install(discovery, versions, fs, process_evidence, selected_install_dir=...)`
returns JSON-serializable evidence and reasons:

- `blocked`: missing AppID, incomplete discovery/process evidence, multiple
  candidates, unsafe paths, unsupported hash/version/size, denied reads, changed
  files, unapproved release or conflicting backup.
- `ready_for_review`: synthetic checks permit a preview, not installation.
- `already_patched`: exact known output hash; no replacement is proposed. This
  does not attest a recoverable backup or implement upgrade/uninstall.

`can_apply` is always false and confirmation is always required. A preview names
only `Ld95.exe`, before/after hashes and sizes, observed identity/change token,
and the proposed backup. Backups are never created here. Existing matching
backups may be proposed for reuse; conflicting content/directories/reparse
evidence are rejected, never overwritten. USR, saves, ini and other mods are not
read or proposed for changes. Unknown EXE hashes are rejected even if their file
version matches. No patch bytes are generated by the planner.

The repository configuration still has `steam_app_id: null` and
`release_approved: false`. The demo's numeric AppID is synthetic and is not a
claim about the game's Steam identity. Real install readiness is intentionally
blocked. The historical m020 output digest remains a target for a later licensed
integration check, not a newly verified release.

## Remaining gates

Verify the actual local app manifest AppID through an authorized read; implement
and review real Windows evidence adapters; test transaction backups/rollback,
concurrent changes and recovery using synthetic faults; then obtain the scoped
final Windows GUI/save/load/restore acceptance. There is no cloud executor,
Actions run, new native executable or host game launch in this milestone.
